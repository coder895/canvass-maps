# Handoff: Surrey-Guildford data

Where this repo stands, and the steps left to turn it into the Surrey-Guildford campaign map.

## Where it stands

- The code is the campaign map, poll map, check-in desk and Voted tab from `coder1893/scc-canvass-maps`, with none of that campaign's data and no Firebase database.
- Without data the maps open with no password and work from exports loaded in the browser. The desk says it isn't switched on yet.
- `data/public.js` (the base map) is still **Surrey City Centre (SRC)**.
- GitHub Pages isn't switched on yet. ArshdeepMutti is a collaborator with write access.

## The data

Two "Full" supporter exports from the campaign database (one sheet each, same 24 columns):

| File | People | What it is |
|---|---|---|
| `Full-2024-10-15-4.xlsx` | 1,570 | The 2024 supporter list. All have a Voter ID. Has Voted 2024: 1,098 yes, 472 no |
| `Full-2026-10-15-5.xlsx` | 3,488 | Supporters identified this election (2026). 3,441 have a Voter ID |

- 1,550 people are in both files, and 20 are only in the 2024 file. Use **both**: the point is to compare 2024 voting with the people identified in 2026.
- Every row is riding `569`, polls `001`–`063` (`999` = no poll, 2 people). Support is `Conservative` or `Conservative-Leaning`. Addresses are Guildford / Fraser Heights (V3R, V4N).
- Columns: `ID, First Name, Last Name, Support, Support Updated, Support 2020, Support 2017, Home Tel, Cell Tel, Addr 1, Addr 2, City, Prov, PCode, Riding, Poll, Poll Margin, Vote At, Has Voted 2024, Has Voted 2020, Has Voted 2017, Nation Builder ID, Party Vu ID, Voter ID`.
- `Addr 1` comes as `" - 11058 147A St "` (no unit, leading dash) or `"1203 - 13450 104 Ave"` (unit first). Strip the leading `"- "` before `listAddress()` in `core.js`, which otherwise returns null.

**Never commit these spreadsheets.** The repo is public. Only the encrypted `data/campaign.enc.js` goes in.

Decisions already made:
- Riding: **Surrey-Guildford**.
- Phone numbers: **include them** (encrypted), so canvassers see them on the map.
- Team password: **generate a strong one** and share it with the team outside GitHub.

## Steps

### 1. Rebuild the base map for Surrey-Guildford

Replace `data/public.js`, keeping its structure: `riding`, `code` (the Elections BC district code), `sources`, `outline`, `polls` (code and rings), `registered`, `results` (`byWay`, `places`, `candidates`, `date`), `names`, `roads`, `streetLabels` and `addresses`. `core.js` reads all of these.

The original was generated by `maps/build_dashboard_data.py`, which isn't in this repo. Reuse it if you have it, otherwise rebuild from the same public sources:

- Elections BC 2024 electoral district boundary and voting areas, registered voters per voting area, 2024 results by voting place, and which voting place each poll used
- BC Digital Road Atlas, for streets and labels
- BC Address Geocoder, for address points

The hosts are `openmaps.gov.bc.ca`, `geocoder.api.gov.bc.ca`, `catalogue.data.gov.bc.ca`, `pub.data.gov.bc.ca` and `elections.bc.ca`. They were blocked in the cloud session but load normally from your own computer.

Then change "Surrey City Centre" to "Surrey-Guildford" in the titles and eyebrow text of `index.html`, `polls.html` and `desk.html`. Check that the 63 polls in the data match the voting area numbers.

### 2. Teach the maps to read the "Full" export

Neither map recognises this format yet. In `core.js`:

- **Recognise the file:** in `sniff()`, a header row with `ID`, `First Name`, `Last Name`, `Support`, `Addr 1`, `Poll`, `Has Voted 2024` and `Voter ID` is a Full export. Tell the 2024 file from the current one by the year in the file name.
- **2024 file → the 2024 lists:** `Has Voted 2024 = Yes` goes to the `voted` list and `No` to the `not` list. Use the same shape as `listFromRows()`: `{ poll, street, phone, reg }`. This drives "Didn't vote in 2024", GOTV routes and focus scores.
- **2026 file → supporters this election:**
  - Per house: build household seeds in the same shape `parseInteractions()` returns (`n.con` / `n.lean` per address and unit, `last` = Support Updated). This drives "Supporters found this election" and the poll map's "now" counts per door.
  - Per poll: a summary for the "Supporters now" colouring, counts and focus table, which today need a Poll Summary (`S.ps`). There's no "no answer yet" share in this export, so leave `unknown` null. Hide the "No answer" shading, column, tooltip text and overview KPI when it's null (`app.js` uses `pct(r.unknown)` unguarded in `pollTip`, `pollCard` and the polls table).
- **Both files → the voters file:** `Voter ID`, address, last name and first name, in the same rows as `voterNosFromRows()`. This is what matches the Elections BC participation report and powers "Has someone voted?". Check against a real participation report that `Voter ID` is the same number as the report's card number.
- **Names and phones per house:** merge both files by `ID`. In the house popups (`houseCard()` in `app.js`, `openHouse()` in `polls.js`), list who lives there: name, unit, phone, 2026 support and whether they voted in 2024.

In `app.js` and `polls.js`:
- Handle the new kind in `loadFiles()` and `applyBuiltIn()`.
- Add the Full exports to the poll map's "save for the team" file (`sealBtn` in `polls.js`), so a newer export can be locked in from the browser later.

### 3. Encrypt the data

- **Write `data/campaign.enc.js`:** it sets `window.CAMPAIGN_ENC = { salt, iterations, iv, data }`.
  - Key: PBKDF2-SHA256, 600,000 iterations, from the team password.
  - `data`: the payload, gzipped and then AES-256-GCM encrypted, all base64.
  - See `deriveKey()`, `decryptBox()` and `sealExtra()` in `core.js`.
- **Check it opens:** the password screen should appear, and the right password should unlock the data on both maps.

### 4. Publish

1. Push to `main`.
2. Under **Settings → Pages**, choose **Deploy from a branch**, branch `main`, folder `/ (root)`, then **Save**.
3. Wait for **"pages build and deployment"** to go green in the **Actions** tab. The site is then at https://coder895.github.io/canvass-maps/

### Optional: check-in desk and sign-in log

- Create a Firebase Realtime Database and put its URL in `desk-config.js`.
- Add the same URL to `connect-src` in the Content-Security-Policy at the top of `index.html` and `polls.html`.
- Publish `database.rules.json` under Realtime Database → Rules.
