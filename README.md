# Campaign canvass maps

A static dashboard for a provincial campaign: supporters found against the votes needed to win, polls shaded by the 2024 result, supporters found, voters not contacted or 2024 supporters who didn't vote, and every contacted household on a labelled street map with one simple filter. `polls.html` is the poll map (focus scores, door-knock routes and printable house sheets), `desk.html` is the check-in desk, and both maps have a **Voted** tab.

**This copy has no campaign data in it yet.** The maps open without a password and work from the exports you load from your own device: Poll Summary, Interactions, the voting lists, the T1 list, the voters file and the Elections BC participation report. Loaded files stay in that browser tab and never leave it.

**The riding.** `data/public.js` is built from BC open data for Surrey City Centre (SRC): Elections BC 2024 boundaries, voting areas, registered voter counts, results by voting place and the poll-to-voting-place assignment; the BC Digital Road Atlas; and BC Address Geocoder address points. For another riding it has to be rebuilt from the same sources, and the riding name in the titles of `index.html`, `polls.html` and `desk.html` changed to match.

**Built-in data, locked with a password.** To have the maps open with your data already in them, the data goes in `data/campaign.enc.js`, encrypted with AES-256-GCM under a key derived from the team password (PBKDF2-SHA256, 600,000 iterations). Without the password the file can't be read, so copying the site or this repository yields nothing usable. Once that file exists the maps ask for the password, and data loaded later on the poll map can be locked with the same password into `data/campaign.extra.enc.js`. There's no tool for making `campaign.enc.js` in this repository yet.

**Who has voted.** Load the Elections BC voting participation report (`VotingParticipationReport….csv`) on either map; nothing needs publishing. Each report adds to the ones already loaded, so load each new one as it comes. The list follows the tab between the two maps and is dropped when you lock or close it. Both maps then show how many have voted in each poll and where. Each map's **Voted** tab has the totals (everyone who has voted against the registered voters, and how many of our supporters), turnout poll by poll, and "has someone voted?" by name and address. Our supporters are matched to the report by voter number from the voters file, which is never shown or searched on the maps. Routes, focus scores and T1 households leave out our people the report shows have voted; where a unit has several of our people and only some are in the report, the report can't say which ones, so only that many are taken off.

**Check-in desk and sign-in log: not set up.** Both need a Firebase Realtime Database. Create one, put its URL in `desk-config.js`, add the same URL to `connect-src` in the Content-Security-Policy at the top of `index.html` and `polls.html`, and publish `database.rules.json` under Realtime Database → Rules. The desk then keeps its shared board there, and each time someone unlocks either map with the password, the page adds one line to `signins`: the time, which map, a random device ID the browser keeps, the browser and device type, and the internet address (looked up from [ipify](https://www.ipify.org), since a page can't see its own). Read it in the Firebase console under Realtime Database → Data → `signins`.

**Publishing.** Turn on GitHub Pages under Settings → Pages: deploy from the `main` branch, root folder.

Libraries: [Leaflet](https://leafletjs.com) 1.9.4, [SheetJS](https://sheetjs.com) 0.20.3, jsPDF and the Firebase web SDK, vendored in `vendor/`.
